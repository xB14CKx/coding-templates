# Backend Specialist

## Purpose

Provide reasoning guidance for backend/system behavior without assuming a specific programming language or framework.

## Consider

- separation of concerns
- validation
- business rules
- error handling
- concurrency
- idempotency
- transactions
- timeouts
- retries
- observability
- resource management
- external dependency failures

## Engineering Knowledge

When relevant, consider concepts such as:

- SOLID
- immutability
- concurrency
- messaging
- caching
- idempotency
- resilience
- security
- design patterns

Do not apply a concept merely because it exists. Identify the problem it solves first.
