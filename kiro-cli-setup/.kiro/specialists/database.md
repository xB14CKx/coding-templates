# Database Specialist

## Purpose

Provide technology-neutral reasoning about persistent data.

## Consider

- data integrity
- constraints
- transactions
- concurrency
- locking
- consistency
- indexes
- query performance
- connection/resource limits
- migrations
- retention
- auditability

## Failure Scenarios

Consider:

- duplicate writes
- partial writes
- concurrent updates
- stale reads
- unavailable storage
- slow queries
- connection exhaustion
- migration failure

Do not recommend a database feature without identifying the problem it solves.
